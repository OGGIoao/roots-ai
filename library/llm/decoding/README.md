# 解码与采样 (知识库 · 大语言模型 · 推理与部署段)

> 模型每一步给词表里每个 token 打一个分。怎么从这些分数里挑出下一个 token, 就是解码: 贪心、按概率抽签、抽签前划掉不靠谱的候选 (top-k、top-p、min-p)、惩罚重复、束搜索, 以及什么时候停。
> 讲义: [TUTORIAL.md](TUTORIAL.md) (两部分, 21 节, 15 张图, 练习和思考题都附折叠的参考答案)。

**只需要 Python**: 实验对象是一个从莎士比亚语料数出来的字符级三元模型 (`toy_lm.py`), 一秒内建好, 不用下载模型, 不用显卡。只有专题 B、C 要加载 0.5B / 1.5B 模型, 在 CPU 上跑。

"今天天气很___" 的 6 个候选: 温度只改差距不改排名; 截断把不靠谱的划掉; 重复惩罚只改一部分 token, 所以能把第一名翻过来。讲义第 2 节逐个手算。

## 实测要点

| 结论 | 数字 | 讲义 |
|---|---|---|
| 贪心会转圈, 而且是必然的 | 5 个开头全部在第 2~4 个字符掉进 "the " 的循环 | 3 |
| 温度 1.0 写出的文字最接近语料本身 | 平均对数概率 -1.94, 语料本身 -1.89 | 4 |
| top-p、min-p 随把握大小伸缩, top-k 是死数 | 没把握时 top-p 留 14 个、top-k 只留 5 个 | 5 |
| 重复惩罚救不了贪心的转圈 | 惩罚加到 2.0 仍然 100% 转圈 | 6.2 |
| 重复惩罚的力度取决于 logits 的整体平移 | 同一分布同样 1.3, "e" 的概率可以是 0.40, 也可以是 0.002; 减法的惩罚纹丝不动 | 6.3 |
| 只有 "按次数" 的惩罚能打破循环 | 频率惩罚 0.3、禁止重复 4 元组: 转圈 0%; 出现惩罚、窗口惩罚: 100% | 7.2 |
| 贪心时模型自带的重复惩罚照样生效 | Qwen2.5 自带 1.1, `do_sample=False` 不会关掉它 | 8.3 |
| 手写的每一步和 transformers 一致 | 2000 组随机打分, 只有并列 token 的取舍不同 | 8.2 |
| 束搜索总分更高, 照样转圈 | 束宽 1→32, 总分 -41.67→-39.79, 全是 "the the" | 9 |
| 三家框架顺序不同, 同样参数不是同一个设置 | Qwen 的采样设置: llama.cpp 在 2000 个上下文里 1640 个留下的候选和 transformers 不同 | 专题 A |
| 真实小模型上, 自带的重复惩罚改的是工具调用的 JSON | 12 个问题, 0.5B 改了 7 条回复 (参数被删、被改), 1.5B 改了 6 条, 其中 3 条连第一个 token 都换了 | 专题 B |
| 贪心换一条计算路径就可能不同 | 1.5B bf16 两条路径 284 个位置里 1 个第一名不同; 0.5B 换成 bf16, 12 条回复里 1 条不同 | 专题 C |

**在项目里** (讲义第 15 节): 小车 v0.4 用 Qwen2.5-1.5B, 自带的重复惩罚把回复的第一个 token 从 `<tool_call>` 压成普通文字; 关掉它, go_to 从 14/30 升到 18/30, "没动" 从 12 局降到 4 局。
