# 学习路线图

> 本文件记录已经商定的整体设计。改动方向时先改这里, 再动代码。
> 最后更新: 2026-10-18

## 1. 两条并行线与汇合点 (2026-10-18 调整)

原先是 LLM → RL → Agent 一条串行线。按真实的依赖关系拆成**两条互不阻塞的线**, 只在两处汇合:

```
LLM 线:   生长树 (注意力 ✅ → 位置 → MoE → 归一化 → 替代架构 → 效率) ──┐
                                                                         ├─→ ⓐ 后训练 (DPO / GRPO) ──→ Agent
具身线:   R0 RL 主干 ─→ R1 仿真器解剖台 ─→ R2 连续控制 ─→ R3 模仿学习 ─┤
          (老虎机…PPO)                                    ─→ R4 扩散策略 ┴─→ ⓑ R5 VLA
```

| 线 / 板块 | 目标 | 总图 | 状态 |
|---|---|---|---|
| LLM 线 | 从 Transformer 长出整棵架构树, 每个节点手写 + 对照实测 | [LLM_TREE.md](LLM_TREE.md) | 进行中 (注意力线完成) |
| 具身线 | 从经典 RL 到 VLA, 全部在仿真里做, 每个节点手写 + 实测 | [EMBODIED.md](EMBODIED.md) | 设计已定, 未开始 |
| 后训练 (汇合点 ⓐ) | 把语言模型当策略做 RL: miniGPT 上的 RL、DPO、GRPO | 第 4 节 | 未开始 |
| Agent | 手写 Agent 循环、工具、记忆、规划, 再对照主流框架 | — | 只有 M1 脚手架 |

- **为什么能并行**: 具身线 R0–R4 只依赖 RL 主干, 与注意力、MoE 等无关; LLM 生长树也不依赖 RL。
- **两个汇合点**: ⓐ 后训练要用具身线 R0 做扎实的 PPO, 以及 LLM 线训出的模型; ⓑ R5 VLA 要用 LLM 线的 Transformer 与多模态知识。
- **RL 主干放在具身线开头**: CartPole、MuJoCo 本来就是控制问题, "为什么要 baseline、为什么 PPO 要裁剪"在控制语境里最直观; 后训练直接复用这里的 PPO。
- **节奏**: "并行"指依赖上互不阻塞, 不是同时学两样。按**节点交替**推进: 一个节点 (讲义 + 实验 + 练习) 完整做完再切换。
- **仓库组织**: 两条线都在主线上, 按目录区分 (`projects/llm-*`、`projects/embodied-*`), 不开长期分支; 两个会话同时推进时用短期分支, 一个节点完成就合并回主线。
- Agent 仍放在最后: 规划与工具使用用 RL 的视角理解会更透。

### 1.1 LLM 板块的主干: 架构生长树 (2026-10-15 商定)

LLM 板块不再是几个并列项目, 而是按 **"从 Transformer 长出来的架构树"** 组织:

```
Transformer → Decoder-only → GPT-2 (llm-minigpt) → LLaMA 配方 (llm-transformer)
                                                        │
       ┌──────────────┬──────────────┬──────────────┬───┴──────────┬──────────────┐
    注意力线        位置编码线       FFN / MoE 线     归一化线      架构替代线      训练/推理效率线
叶子 = 具体的前沿模型, 拆解它组合了哪些节点
```

- **覆盖范围**: 注意力与长上下文、MoE 与稀疏计算、非 Transformer 与混合架构、训练与推理效率, 四条前沿分支全部覆盖。
- **每个节点回答四个问题**: 解决了父节点的什么问题 → 代价 → 最小实现 + 与父节点在同一任务上的对照实测 → 哪些模型用了它。
- **节点深度**: 每个节点都手写实现 + 对照实测, 配三级练习。
- **解剖台**: 批量读取真实开源模型的 `config.json` (不下载权重), 用真实数据核对树上的每条论断。
- **紧跟前沿但不凭记忆**: 写前沿模型节点前先查原始技术报告和公开配置, 讲义标注来源与日期。
- **顺序**: 先搭树的骨架 (总图 + 解剖台 + 统一的对照实验框架, 把现有项目挂上去), 再按树的顺序补讲义和新节点。
- 树也连着其它板块: 后训练 (汇合点 ⓐ) 是"后训练"枝, 具身线的 VLA (汇合点 ⓑ) 是"多模态"枝。

## 2. 每个模块的三件套

| 组成 | 作用 |
|---|---|
| 讲义 `TUTORIAL.md` | 讲透原理与代码。样章: [llm-minigpt/TUTORIAL.md](../projects/llm-minigpt/TUTORIAL.md) |
| 参考实现 | 仓库里现有的代码, 也是练习的标准答案 |
| 手写练习 | 三级递进, 见第 3 节 |

**讲义规范** (以 minigpt 样章为准; 篇幅已确认够详细, 2026-10-15):
- 所有数字、形状、输出都在本机实测, 不用示意值。
- 每节: 一句话 → 直觉 → 公式逐项 → 逐行拆解 → 带数字的例子 → 动手验证。
- 本仓库真实踩过的 bug 单独标注, 写清"为什么当时没发现"。
- 练习附折叠答案。
- 公式用 LaTeX: 块级用 ```` ```math ````, 行内用 `` $`...`$ `` (紧挨中文时也能稳定渲染)。
- 分两部分: 第一部分读懂代码, 第二部分是**延伸专题**; 每个专题配一个 `experiments/` 下的实验脚本, 正文数字即脚本输出。
- 开头有带锚点链接的目录。
- **图解** (2026-10-17 起): 关键技术配图, 不只靠文字和代码。两类图:
  - 结构图 (数据流、张量形状、谁和谁对应): 由 `figures/make_diagrams.py` 生成 SVG;
  - 数据图 (实测曲线、对比): 由 `figures/make_charts.py` 从 `results/` 生成 SVG, 实验重跑后重新生成即可;
  - 每张图紧跟一段 **"怎么读"**, 并配有对应的数据表; 配色用 dataviz 规范并经脚本验证 (色盲可分);
  - 不透明浅色背景 (GitHub 深色模式下也可读); 每张图都要渲染出来亲眼检查过再提交。
- **代码注释**: 每一步写明在做什么、为什么, 以及张量形状; 讲义里的代码片段直接截取自源文件, 与真实代码一字不差。
  补注释时用"输出指纹"检查行为未变 (同种子下全部输出逐位相同)。

LLM 板块讲义采用上述"讲解为主"的写法; **RL 板块改为案例驱动**, 见第 4 节。

## 3. 手写练习: 三级递进

同一个功能, 逐级拿掉"扶手":

| 级别 | 给出 | 自己写 |
|---|---|---|
| ① 填空 | 完整文件, 关键函数体留 `TODO` | 函数体 |
| ② 接口 | 函数签名 + 测试 | 整个模块 |
| ③ 白纸 | 一句验收标准 (如 "nano 5000 步内 val_loss < 2.0") | 从数据到生成的全部代码 |

**判定标准由测试给出**:
- 形状正确;
- 与参考实现逐数值比对 (同权重同输入, 误差 < 1e-6);
- 闭环硬指标: 初始 loss ≈ ln(V)、训练达到目标 loss、能生成。

**卡住时的提示规则 (分级提示)**: 先指方向 → 再指出哪一行 → 最后才给代码。
每次只升一级, 是否要下一级由学习者决定。写错的地方记入个人"错题本"。

**LLM 板块的最小闭环**:
- BPE: 训练 → 编码 → 解码, 一字不差还原
- GPT: 注意力 → Block → 模型 → 训练到 loss < 2.0 → 生成
- QLoRA: **手写 LoRA 层** (不用 peft) → 套到真实模型上微调 → 推理对比; 量化部分调库

## 4. RL: 主干在具身线, 后训练在汇合点 ⓐ, 案例驱动

每个案例的结构:

```
一个具体问题 → 先用最朴素的办法试 → 看它怎么失败 → 引出概念
→ 写最小代码 → 做实验对比 → 留一个"改一处会怎样"
```

RL 板块以练习为主、讲解为辅: 先按直觉写, 失败之后再学正确做法。

```
具身线 R0: 经典 RL 主干 (两个方向的共同地基, PPO 必须扎实)
  ① 老虎机                   探索与利用, ε-greedy, UCB
  ② 冰面迷宫 FrozenLake        状态, 价值, Q-learning
  ③ CartPole                 策略梯度 REINFORCE, baseline
  ④ PPO                      让训练更稳

具身线 R1–R5: 见 EMBODIED.md (仿真器解剖台 → 连续控制 → 模仿学习 → 扩散策略 → VLA)

汇合点 ⓐ 大模型后训练 (需要 R0 的 PPO + LLM 线的模型)
  P1 让 miniGPT 学会一个可验证的目标     把语言模型当策略做 RL
  P2 偏好对齐                          DPO (0.5B + LoRA)
  P3 数学题                            GRPO (0.5B + LoRA, 显存需实测)
```

编号说明: 原分支 A 的 A1–A3 改为 P1–P3 (Post-training), 避免和 LLM 生长树注意力线的 A1–A7 撞号; 原分支 B 的 B1–B4 并入具身线 R2–R5 (用 R = Robot, 因为生长树的 B 线、E 线已占用这些字母)。

## 5. 运行环境

| 用途 | 环境 |
|---|---|
| LLM 线、后训练的小模型 | 本机 Windows, conda 环境 `mlc`, RTX 5060 8GB |
| 具身线 R0–R3 (gymnasium、mujoco: 纯 pip 轮子, 不依赖也不改动 torch) | 本机 `mlc`, 装之前先用 `pip install --dry-run` 确认不会动 torch |
| 具身线 R4–R5 中会锁定 torch 版本的工具链 (LeRobot 等) | 单独的 conda 环境 `emb`, 不装进 `mlc` (避免重演 README 里 `ml` 环境被覆盖的事故) |
| 本机放不下的大模型 / Windows 跑不通的工具链 (Isaac Lab 等) | 云服务器 (不使用 WSL2) |
| 真机硬件 | 不使用, 全部仿真 |

已知限制: 8GB 显存无法微调 OpenVLA (7B) 一类的大型 VLA, R5 采用小模型。
各工具在 Windows 上能否运行, 动手前逐个实测, 不做假设。
