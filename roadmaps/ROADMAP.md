# 路线图

> 本仓库要做成什么、按什么顺序做、为什么这样排。讲义和练习的写法见 [CONTRIBUTING](../CONTRIBUTING.md)。
> 最后更新: 2026-10-21

## 0. 终点

整条链路最后要跑通的一个 demo, 每一环都是本仓库自己写的:

```
自己预训练的小模型 → 自己做后训练 → 跑在自己写的推理服务上 → 被自己写的 Agent 调用 → 一句话指挥仿真里的四足机器人走过去
```

下面两条线和 Agent 板块都朝这个终点走。

## 1. 两条并行线与汇合点

```
LLM 线:   生长树 (注意力 ✅ → 位置 → MoE → 归一化 → 替代架构 → 效率) ──┬──────────────→ ⓐ 后训练 (DPO / GRPO)
                                                                         │                      ↑ 需要 R0 的 PPO
具身线:   R0 RL 主干 ─┬─→ R1 本体与经典控制 → R2 RL 步态 → R3 模仿学习 → R4 多峰行为 │
          (老虎机…PPO) │   └──────── 同一台 Pupper 四足 ────────┘                    ↓
                       └──────────────────────────────────────────────→ ⓑ R5 语言与视觉
                                                                         ↑
Agent 板块:  原子循环 → 工具调用 ──────────────────────────────────────────┘ → 记忆、规划 ...
```

| 线 / 板块 | 目标 | 总图 | 状态 |
|---|---|---|---|
| LLM 线 | 从 Transformer 长出整棵架构树, 每个节点手写 + 对照实测 | [LLM_TREE.md](LLM_TREE.md) | 进行中 (注意力线完成) |
| 具身线 | 从经典 RL 到"听一句话、看一眼画面, 自己走过去", 载体是一台 Pupper 四足, 全部仿真 | [EMBODIED.md](EMBODIED.md) | 进行中 (R0 ① 老虎机完成) |
| 后训练 (汇合点 ⓐ) | 把语言模型当策略做 RL: miniGPT 上的 RL、DPO、GRPO | 第 3 节 | 未开始 |
| Agent | 手写 Agent 循环、工具、记忆、规划, 再对照主流框架 | — | 未开始 |

- **为什么能并行**: 具身线 R0–R4 只依赖 RL 主干, 与注意力、MoE 等无关; LLM 生长树也不依赖 RL。
- **两个汇合点**:
  - ⓐ 后训练要用具身线 R0 做扎实的 PPO, 以及 LLM 线训出的模型;
  - ⓑ **R5 语言与视觉同时汇合 LLM 线和 Agent 板块**: R5.1 让 LLM 用工具调用 (`walk`、`turn`、`stop`) 驱动 R2 的步态策略, 这就是 Agent 的"循环 + 工具"; R5.3 的小型端到端 VLA 用 LLM 线的 Transformer。
- **具身线的载体**: R1–R5 始终是同一台 Pupper v3 四足, 与 Datawhale《动手学具身智能》的 CS123 四足课逐章对齐 (第 1–5 章 → R1, 第 6 章 → R2, 第 7–8 章 → R5)。Datawhale 作为对照读物, 不复制其内容; 模型文件从 MIT 许可的上游取, 详见 EMBODIED.md 文末。
- **RL 主干放在具身线开头**: CartPole、MuJoCo 本来就是控制问题, "为什么要 baseline、为什么 PPO 要裁剪"在控制语境里最直观; 后训练直接复用这里的 PPO。
- **Agent 不放在最后**: 它的"循环 + 工具调用"部分要在 R5.1 之前做完, R5.1 是它的第一个真实场景 (工具有物理后果, 失败要处理); 记忆、规划等后续部分仍在后面, 用 RL 的视角理解会更透。

### 1.1 LLM 线的主干: 架构生长树

LLM 线不是几个并列项目, 而是按 **"从 Transformer 长出来的架构树"** 组织:

```
Transformer → Decoder-only → GPT-2 (llm-minigpt) → LLaMA 配方 (llm-transformer)
                                                        │
       ┌──────────────┬──────────────┬──────────────┬───┴──────────┬──────────────┐
    注意力线        位置编码线       FFN / MoE 线     归一化线      架构替代线      训练/推理效率线
叶子 = 具体的前沿模型, 拆解它组合了哪些节点
```

- **覆盖范围**: 注意力与长上下文、MoE 与稀疏计算、非 Transformer 与混合架构、训练与推理效率。
- **每个节点回答四个问题**: 解决了父节点的什么问题 → 代价 → 最小实现 + 与父节点在同一任务上的对照实测 → 哪些模型用了它。
- **解剖台**: 批量读取真实开源模型的 `config.json` (不下载权重), 用真实数据核对树上的每条论断。
- **紧跟前沿但不凭记忆**: 写前沿模型节点前先查原始技术报告和公开配置, 讲义标注来源与日期。
- 树也连着其它板块: 后训练 (汇合点 ⓐ) 是"后训练"枝, 具身线的 VLA (汇合点 ⓑ) 是"多模态"枝。

## 3. RL: 主干在具身线, 后训练在汇合点 ⓐ, 案例驱动

每个案例的结构:

```
一个具体问题 → 先用最朴素的办法试 → 看它怎么失败 → 引出概念
→ 写最小代码 → 做实验对比 → 留一个"改一处会怎样"
```

```
具身线 R0: 经典 RL 主干 (两个方向的共同地基, PPO 必须扎实)
  ① 老虎机 ✅                 探索与利用, ε-greedy, 乐观初值, UCB
  ② 冰面迷宫 FrozenLake        MDP, 价值迭代, 蒙特卡洛, TD, Q-learning
  ③ CartPole                 DQN; REINFORCE → baseline → Actor-Critic
  ④ PPO                      PPO-Clip + GAE, 让训练更稳

具身线 R1–R5: 见 EMBODIED.md, 全部在同一台 Pupper 四足上
  (本体与经典控制 → RL 步态 → 模仿学习 → 多峰行为 → 语言与视觉)

汇合点 ⓐ 大模型后训练 (需要 R0 的 PPO + LLM 线的模型)
  P1 让 miniGPT 学会一个可验证的目标     把语言模型当策略做 RL
  P2 偏好对齐                          DPO (0.5B + LoRA)
  P3 数学题                            GRPO (0.5B + LoRA, 显存需实测)
```

编号说明: 后训练用 P (Post-training), 具身线用 R (Robot), 避免和 LLM 生长树已占用的字母撞号。

## 4. 往终点走的扩展方向

| 方向 | 笔记本能做到哪 | 需要上云的部分 |
|---|---|---|
| 把模型做大 | miniGPT 量级, Shakespeare 语料 | 真实语料上预训练约 1 亿–10 亿参数的模型; 多卡训练 (DDP / FSDP / ZeRO) |
| 后训练 | 0.5B + LoRA 做 DPO / GRPO | 全参数或更大的模型 |
| 推理服务 | KV cache 已有实验 | 手写迷你推理服务 (分页 KV、连续批处理、量化) 的并发压测 |
| Agent | 全部本地 | 基本不需要 |
| 机器人 | MuJoCo 单环境仿真 | 大规模并行环境、Isaac Lab 等 Windows 跑不通的工具链 |

## 5. 运行环境与上云原则

| 用途 | 环境 |
|---|---|
| 测量平台 (讲义里的数字都出自这里) | Windows 11 笔记本, RTX 5060 Laptop 8GB, Python 3.10 |
| LLM 线、后训练的小模型 | 主环境 (安装见根目录 README) |
| 具身线 R0–R3 (gymnasium、mujoco: 纯 pip 轮子, 不依赖 torch) | 主环境, 装之前先用 `pip install --dry-run` 确认不会动 torch |
| 具身线 R4–R5 中会锁定 torch 版本的工具链 | 单独的 conda 环境, 不装进主环境 |
| 笔记本放不下的模型 / Windows 跑不通的工具链 | 云服务器 |
| 真机硬件 | 不使用, 全部仿真 |

**上云原则**: 只在笔记本**实测**撞墙 (显存溢出、要跑好几天) 之后才上云, 并把这个数字写进讲义。上云的部分也按对照实验来写: 笔记本 vs 云 GPU、单卡 vs 多卡, 让读者看到"为什么需要多卡", 而不只是"换了台机器"。

已知限制: 8GB 显存无法微调 OpenVLA (7B) 一类的大型 VLA; R5 采用分层结构, 端到端部分只训练输出速度指令的小模型。
各工具在 Windows 上能否运行, 动手前逐个实测, 不做假设 (Datawhale 的四足课写的是 Ubuntu / macOS / WSL2)。
